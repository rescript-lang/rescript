# Checkpoint 11: legacy PPX boundary

Status: the frozen AST 0 adapter is isolated and validated. Persistent AST 0
workers and a newer protocol remain separate PPX goals; external PPXs still
run as interruptible child processes.

`compiler/core/legacy_ppx_adapter.ml` owns the frozen AST 0 file protocol:
conversion to AST 0, Marshal serialization, file writes, external execution,
file reads, deserialization, and result conversion back. `cmd_ppx_apply.ml`
calls the adapter only when `-ppx` arguments are present. The no-PPX branch
returns the input tree unchanged, except for the existing explicit AST
conversion test mode. A completed input write propagates close/flush errors.
`Parsetree0` and the bridge mappings are unchanged.

The five-run gate used Linux 7.0.12-linuxkit on aarch64, `/tmp` on overlayfs,
the Dune `dev` profile, one compiler domain, `REWATCH_BIN_ANNOT=0`, and frozen
lookup. It alternated a plain build and an identity-PPX build of the same
four-module project; one module has an interface, so the PPX handled five ASTs
per build. Both modes compiled four modules on every run and generated the
same 20 JavaScript, CMI, and CMJ artifacts by SHA-256. The no-PPX traces had
zero `ppx.*` phases; identity-PPX traces had all seven expected phases.

| Phase | Median worker time | Median OCaml allocation | Calls per build |
| --- | ---: | ---: | ---: |
| AST 0 conversion | 0.024 ms | 19.7 KiB | 5 |
| Serialization | 0.021 ms | 5.3 KiB | 10 |
| File writes | 0.120 ms | 1.5 KiB | 5 |
| External execution | 27.762 ms | 697.7 KiB | 5 |
| File reads | 0.071 ms | 6.8 KiB | 10 |
| Deserialization | 0.034 ms | 15.3 KiB | 5 |
| AST 0 conversion back | 0.027 ms | 23.8 KiB | 5 |

Median elapsed build time was 33.721 ms without a PPX and 82.591 ms with the
identity PPX. Worker-phase timings exclude Rewatch scheduling and other build
work; external execution includes process startup and the identity PPX's file
copy. The adapter's conversion, serialization, file I/O, and deserialization
were small compared with external execution. Raw CSV and per-request traces
are in `/tmp/rewatch-step11-close-gate` in this workspace. The Rewatch executable
SHA-256 was
`0cc5624db1e3868293fec57cdb38a00b3375c57fcd9f4cf2e413007d2e3dfb20`;
the standalone compiler SHA-256 was
`f10eea6f60ed87b055abdb8f5104a434aa3430fe7b0c9d5caa87038de503b827`.

The existing `sury-ppx` fixture also built successfully through the adapter:
the generated JavaScript included the transformed schema declaration. Its
single PPX execution took 22.547 ms, versus 0.166 ms across the conversion,
serialization, file I/O, and deserialization phases. This is one traced build,
so it is a functional check and cost example rather than a repeatable
performance comparison.

`make test-syntax` passed the existing AST 0 mapping fixtures; `make test`
passed the compiler, standard-library, and JavaScript suites; the OCaml
Rewatch port suite passed; and the identity-PPX gate passed. The PPX adapter
does not change the frozen AST 0 shape or add conversions to non-PPX requests.
