# Embedded compiler baseline: 2026-09-30

Source commit: `ef0a737a8a18a6b2d50af2aefb98870e3cf09c1b`. Host: `Linux-7.0.12-linuxkit-aarch64-with-glibc2.41`; 12 logical CPUs, four compiler domains, Dune default development profile. One unmeasured warm-up and five measured samples per scenario and annotation mode. Annotation settings were interleaved in alternating order. The compiler and executable SHA-256 values and all fixed settings are in [metadata](baseline-2026-09-30.json); all 165 measured requests are in [CSV](baseline-2026-09-30.csv).

Each sample used a fresh project copy. Clean, no-op, implementation edit, shared-interface edit, GenType, identity PPX, and restart use the focused fixtures. The `wide-*` cases use the 201-module immutable-interface fixture. No-op is a new build process over unchanged artifacts. Restart is a new process after a completed build and source edit; it follows the same CLI compilation path as edit, and is recorded separately to make process restart explicit. PPX uses a file-copying external executable, so it measures the legacy AST protocol and process boundary without a transformation.

Wall time includes process startup. CPU time and peak RSS come from Linux `wait4`; allocation is the embedded OCaml process total from `REWATCH_GC_STATS_FILE` and excludes external PPX allocation. Artifact counts and bytes include generated AST, CMI, CMJ, annotations, JavaScript, maps, and TypeScript, excluding files present before the build. Every table value is the median of five samples. These are same-host baselines for subsequent checkpoints, not portable latency targets.

On the wide clean fixture, enabling annotations increased median wall time from 79.3 to 116.6 ms, embedded allocation from 9.4 to 23.3 MB, and generated files from 1,409 to 2,014. The `0` and unset settings were both measured; GenType currently retains annotation-related work in both modes. The follow-on checkpoints will remeasure this exact fixture and use the full integration suites for artifact and diagnostic parity.
