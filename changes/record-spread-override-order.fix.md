- Fix evaluation order for a record spread `{...base, field: value}` compiled to a JavaScript object spread (a record type with an optional field, or with 20 fields or more): the base is copied before an override that needs statements (such as a `try`) is evaluated, so an override's mutation of the base no longer shows up in the copy; overrides run in the order the record type declares its fields; and fields assigned to the result afterwards are set after them, in source order, with values that can read the result.
